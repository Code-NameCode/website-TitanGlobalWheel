Site-Wide Findings

Patterns that show up across the site. Fix these once in the partials and every page benefits.

What's working well

  • Single H1 per page on all 20 pages — no H1 cannibalization.
  • Alt text is universal — 0 of 129 images are missing alt.
  • JSON-LD on 18 of 20 pages, with Organization + BreadcrumbList site-wide and Product/Service/FAQPage layered on commercial pages.
  • hreflang="en-za" on 19 of 20 indexable pages — every page that should be indexed (404 correctly omits it) declares its locale to Google.
  • One canonical URL per page (404 page is the only exception, which is correct — 404s shouldn't declare a canonical). On legacy article URLs the canonical points to the new /blog/<slug>/ pattern, consolidating link equity.
  • Real /blog/<slug>/ URL pattern for all 50 news articles — the legacy /src/news/articles/ path is kept for backward-compat but its canonical folds onto /blog/.
  • All images use WebP (logos remain PNG, which is correct for crisp small graphics).
  • Zero render-blocking external CSS — every page inlines its CSS inside the <style> block, eliminating the stylesheet round-trip.
  • Zero external JS files on most pages; only News (news-index.js) and Contact (EmailJS SDK from CDN) pull scripts.
  • Google Fonts is preconnected on every page.
  • Open Graph + Twitter card tags are set on every page with a shared 1200×630 og-share.png.
  • Hardened contact form: required-field indicators, per-field validation, and a clean() sanitizer that strips HTML tags, neutralises EmailJS / Mustache template syntax, and removes CR-LF (so email header injection like Subject: x Bcc: … can't escape the field).
  • Numbered pagination on news.html (12 articles per page, ‹ 1 2 3 4 5 ›) with fast scroll-reveal animation (~0.35s).

What still needs attention

  • LCP images rarely use fetchpriority="high" — only 4 of 20 pages hint the LCP image. Add fetchpriority="high" + loading="eager" to the hero image, and let everything else stay loading="lazy". Single biggest LCP win still on offer.
  • 81 of 129 images are missing width/height (63%). Without intrinsic dimensions the browser can't reserve space → CLS hits. Add explicit width="…" height="…" on every <img>.
  • No <picture> with AVIF source anywhere — only repairs.html uses <picture> (WebP only). Switching to <picture><source type="image/avif" …><source type="image/webp" …><img …></picture> typically saves another 25–35% on top of the WebP work.
  • No <link rel="preload"> for the LCP image on most pages. Only repairs.html preloads anything. Preloading the LCP image is a strong LCP signal.
  • No preconnect to a CDN / image origin — only Google Fonts is preconnected. If images and CSS are served from a dedicated subdomain (e.g. cdn.titanglobalwheel.co.za), preconnect there too.
  • Two titles are over 60 chars: rims.html (62) and featured.html (67). Google will truncate them in SERPs. Trim to ≤60.
  • 4 of 20 meta descriptions are below 50 chars: Home (12), About (18), Accessories (26), Featured Products (5). Tighten to use the full snippet real-estate and include a CTA.
  • Privacy & Cookies policies have no JSON-LD. They should at least declare WebPage + BreadcrumbList for consistency.
  • Pre-existing: repairs.html links to /earthmoving.html — an industry page that was never built. Static-file 404 from the link checker. Either build the page or remove the card.
  • 404 page returns HTTP 200 from the static dev server. Confirm the production host is configured to serve 404.html with a real 404 Not Found status (this is a host config, not a code change).
