04

Performance & Core Web Vitals

Page experience is a confirmed ranking input via Core Web Vitals. The live WordPress stack loads Elementor, WooCommerce, Yith wishlist/compare, Contact Form 7, TablePress and jQuery on every page — including on a brochure site with no shopping cart in use.

Live WordPress — what every page visit downloads

  • 63 external stylesheets — Elementor Pro, WooCommerce, Yith, Bootstrap 3.3.7, FontAwesome, per-post Elementor CSS…
  • 50 external scripts including jQuery 3.7.1 and jQuery Migrate, blockUI, wc-add-to-cart, Swiper, dataTables
  • WooCommerce cart JS on every page for a site with no functional checkout
  • 163 KB of HTML before a single image or font is fetched
  • Multiple render-blocking resources in <head> — mobile LCP realistically 4–7 s on 4G

Static rebuild — what every page visit downloads

  • 3 small CSS files + 1 inline block — site, mobile-nav and page styles
  • 3 external scripts (GA4 gtag + site JS); no jQuery, no framework
  • 79 KB HTML — half the live homepage before assets
  • Entire site's CSS+JS totals 102 KB — smaller than the live homepage HTML alone
  • Static files serve trivially from CDN/cache — mobile LCP realistically under 2.5 s

05

Technical SEO & Indexation Quality

Both sites have valid sitemaps and are crawlable — but what is in the sitemap matters as much as its existence. The live sitemap actively wastes crawl budget and creates duplicate-content risk.

Live WordPress sitemap: 89 URLs

The page-sitemap contains 43 pages. At least ten are WooCommerce/utility boilerplate that should never compete for rankings:

/cart//checkout//my-account/ /wishlist//yith-compare//sample-page/ /shop//shop-2//sale//business-home/

Plus overlapping near-duplicates competing with each other: /agricultural/ vs /agriculture-tractor-tyres/, /news/ vs /articles/, /military/ vs /military-rims/ vs /military-tyres/.

Blog URL slugs include /6037-2/ (auto-generated ID) and /titan-♥/ (an emoji URL that mangles when shared).

Static rebuild sitemap: 74 URLs

  • Zero utility pages — every URL is indexable, canonical content
  • Hand-written robots.txt blocking dev artefacts (backups, partials, working files) — the live robots.txt is the WordPress default
  • Sitewide canonical tags plus granular robots directives: max-snippet:-1, max-image-preview:large
  • hreflang="en-za" signals the correct regional target — live site declares New Zealand (en-NZ)
  • Clean, descriptive slugs under /blog/
Live-site defect worth knowing about: the production site tells Google its content is in en-NZ (New Zealand) and its social locale is en_US — for a company whose entire market is South Africa and sub-Saharan Africa. The rebuild corrects this with lang="en", hreflang="en-za" and geo.region="ZA" meta. Misconfigured language/region signals dilute local relevance for exactly the queries that matter most here.
06

Structured Data & Rich Results

Schema markup is what unlocks star ratings, FAQ dropdowns, product details and knowledge-panel enrichment in Google's results. The live site ships only the three types its SEO plugin emits by default.

Live WordPress — 3 types, plugin defaults

OrganizationWebPageBreadcrumbList

No Product, no FAQ, no Service — no rich-result eligibility anywhere on the site. The Organization node also carries a 398×40 logo as its only image.

Static rebuild — 25+ types, purpose-built

FAQPage ×3 Product OfferCatalog ×10 Service Organization (address, contact, areaServed, founding) WebSite BreadcrumbList ×8 NewsArticle ×52 CollectionPage Brand

Product and OfferCatalog markup on catalogue pages, FAQPage where Q&A content exists, and a consistent NewsArticle graph across all 52 blog articles — every one carrying headline, image, dates and publisher.

Rich-result upside: FAQ markup alone can add expandable Q&A to search listings, measurably increasing SERP real estate and CTR. Product/OfferCatalog markup makes the rim and tyre catalogues eligible for product-style presentation. The live site currently qualifies for none of this.
07

Content Quality & Depth

The rebuild doesn't just match the live content — it curates and extends it.

52 vs 46 articles

All 46 live posts migrated into the rebuild, plus six new commercial guides (e.g. "LSW vs Duals: Choosing the Right Wheel Configuration", "Why Choose LSW Tyres") written to capture genuine search queries rather than mirror Facebook posts.

Low-value posts tamed, not deleted

Social reposts ("Happy Youth Day", emoji-laden status mirrors hotlinking fbcdn emoji images) dilute site quality on the live site. The rebuild keeps the archive but indexes only structured articles with proper metadata.

AI-search surface

llms.txt + llms-full.txt give ChatGPT, Perplexity and Copilot a structured company profile, product index, contact details and FAQ — a channel the live WordPress site has zero presence in.

08

Where the Live Site Still Wins — and the Honest Gaps

The rebuild is not flawless. These are the live site's genuine advantages and the items the rebuild should address.

Live site advantages

  • 7 years of domain equity — indexed since 2019, with referring domains pointing at current URLs. This is real ranking capital.
  • 4 tool pages the rebuild lacks: /tyre-pressure-calculator/, /load-calculator/, /tyre-spec-chart/, /rim-size-chart/ — genuinely useful, link-worthy utilities that should be ported to the rebuild.
  • Deeper page coverage — industry sub-pages (irrigation, implements, forestry, tractors/harvestors) and a partners page that the rebuild folds into broader pages.

Rebuild pre-launch fixes

  • Backup files in the deploy directory — industries - Backup.html, rims - backup.html, tyres - Copy.html, original-index.html are robots-disallowed but should not ship at all.
  • news.html vs news2.html — verify each carries a distinct canonical so they can't compete.
  • Sitemap lastmod dates — a few predate the latest file edits (e.g. homepage lastmod 2026-08-06, file updated 2026-09-30). Refresh before submission.
  • Port the 4 calculator/chart tool pages from the live site — they earn links and long-tail queries.

Launch Checklist

Ordered by impact. Items 1–2 are non-negotiable; the rest are quick wins.

Critical — before deploy

  • Build the full 301 redirect map — all 89 live URLs (46 posts + 43 pages) to their new counterparts, including /6037-2/ and the emoji post, plus /wp-content/uploads/… image URLs referenced by old articles and external links.
  • Exclude backup/dev files from the deploy — remove the four backup HTML files rather than relying on robots.txt.
  • Verify news.html / news2.html canonicals are distinct and intentional.

Recommended — first month after launch

  • Refresh sitemap lastmod dates and resubmit in Google Search Console; watch Coverage for redirect/404 surprises for 4 weeks.
  • Port the 4 calculator/chart tool pages from the live site (tyre-pressure, load, tyre-spec, rim-size) — proven utility content with existing demand.
  • Re-test all structured data in Google's Rich Results Test post-deploy.
  • Benchmark Search Console exports (clicks, impressions, CTR, position) on launch day so the +CTR and +traffic projections can be verified with real data.
Bottom line: the static rebuild is the better site by a wide, measurable margin — 80 vs 44, with half the page weight, 95% fewer blocking requests, purpose-built metadata on every page, rich-result schema, correct South African targeting, and an AI-search surface the live site lacks entirely. Launch it with the 301 redirect map and the realistic expectation is a step-change in organic performance within one to two quarters — and it protects the one asset where the live site still leads.
